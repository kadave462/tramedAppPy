What We're Building

Pharmacie Tramed already runs Ishyiga POS for core transactions — sales recording, stock tracking, and alerts. This project builds the intelligence layer on top: turning raw Ishyiga data into predictions, automation, and insights that increase profitability. Every solution is documented as a replicable blueprint for other pharmacies across Rwanda.

Forecasting Model — How It Works

1

Daily aggregation: Pulls all SaleItems for a product over the last 90 days, groups by date, fills missing days with zero — complete daily time series.

2

Day-of-week multipliers: Each weekday's mean is divided by the overall mean to produce a multiplier (e.g. Mondays sell 30% more → 1.3). Captures weekly pharmacy traffic patterns.

3

Linear trend fit: Deseasonalises the last 30 days, then fits linear regression via numpy.polyfit. Slope shows whether demand is growing or shrinking.

4

Forward projection: predicted_day = trend(index) × dow_multiplier, clamped ≥0. Produces a 30-day daily forecast.

5

Reorder logic: reorder_qty = forecast_14d + (avg_daily × 7 safety days) − current_stock. Lead time 3 days. Urgency: Critical ≤ lead time, Urgent ≤ safety buffer, Soon ≤ 14 days, OK otherwise.

Loyalty Points Rules

Earning
  • • Minimum purchase: 1,000 RWF
  • • Base rate: 1 pt per 100 RWF
  • • Bronze ×1.0 · Silver ×1.5 · Gold ×2.0
  • • Tier based on lifetime points (never resets)
Tiers & Redemption
  • • Bronze: 0–499 pts · Silver: 500–1,999 pts · Gold: 2,000+
  • • Redemption: 100 pts = 500 RWF discount
  • • Max redemption per sale: 50% of sale value
  • • WhatsApp notification: Kinyarwanda, auto-generated

Recent Changes — June 2026

Bug Fix Jinja2 TemplateSyntaxError on customers/<id>

customer_detail.html line 76 used |list[:5] inside a {% for %} block. Jinja2 does not allow slice notation directly after a filter — the parser expects %}, not [. Fixed by wrapping in parentheses: (acct.transactions|sort(...)|list)[:5].

Bug Fix UndefinedError: 'today' is undefined on customers/<id>

The template uses today.date() (reminder date comparison) and today.strftime(...) (default date input value) but today was never passed by the customer_detail route. Fixed by adding today=datetime.now() to the render_template call in app.py.

Feature Customer search on /customers

Added a search bar in the customer list header. Filters by name or phone (case-insensitive ilike) via ?q= query param — no JavaScript needed, plain GET form. A "Clear" link appears when a search is active. The count badge switches from "X registered" to "X found" when filtered. Changes: app.py (route reads q, filters query, passes q to template) + customers.html (search form in header).

Feature WhatsApp reorder notifications on /forecast

The forecast page now shows a "Send Reorder via WhatsApp" panel between the summary strip and the table. It reuses the existing get_supplier_reorder_messages() function from retention.py (which groups critical/urgent/soon products by supplier and builds a pre-written order message). Each supplier gets one row: product list with urgency markers (⚠ for critical/urgent) and a green WhatsApp button that opens the message pre-filled. Panel is hidden when all stock is healthy. Changes: app.py (passes supplier_msgs to forecast template) + forecast.html (new panel).
