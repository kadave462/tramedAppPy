What was built, what still needs doing, and exactly how to finish it — June 2026

What Automation Means in This Project

Right now every notification in the system — medication reminders, supplier reorders, loyalty messages — requires a staff member to open the app, find the message, and click "Open in WhatsApp". That is better than nothing but it still depends on a human remembering to check the dashboard.

The goal of automation is to make the system push information out on its own, on a schedule, without anyone having to log in. Three jobs have been identified:

1.
Weekly reorder summary → pharmacist
Every Monday at 08:00, send the pharmacist a WhatsApp listing every product that needs restocking, with urgency level and quantity.
2.
Daily medication reminders → patients (not yet built)
Every morning, check all MedicationSchedule rows where next_reminder_date = today and send a personalised WhatsApp to each patient.
3.
Weekly supplier reorder messages → suppliers (not yet built)
Every Monday, send each supplier a grouped order message for their products that are running low — the message text already exists, it just needs to be sent automatically.

What Has Been Built

✓ APScheduler integrated into Flask (app.py)

flask-apscheduler is configured and started when the app boots. A cron job named weekly_reorder_summary is registered to fire every Monday at 08:00. It runs inside the Flask app context so it has full access to the database. use_reloader=False is set to prevent the job firing twice in development mode.

✓ Notifier module (notifier.py)

Wraps the Twilio SDK. send_whatsapp(to, body) reads credentials from environment variables at call time. If credentials are not configured (still the placeholder values from .env), it prints the message to the terminal instead of crashing. This means the scheduling logic works immediately — it just won't send a real WhatsApp until Twilio is set up.

✓ Pharmacist summary message builder (retention.py)

get_pharmacist_reorder_summary() queries all products, runs the forecast, and builds one consolidated WhatsApp message with every product that needs restocking — including urgency emoji (🔴 Critical, 🟠 Urgent, 🟡 Soon), days of stock remaining, and recommended order quantity. Returns None if all stock is healthy (no message sent that week).

✓ Environment config (.env)

All credentials live in .env, loaded at startup via python-dotenv. No credentials are hardcoded. The file has placeholder values and comments explaining exactly what each variable is.

What Still Needs to Be Done

! 1. Set up Twilio and fill in .env

Without this, messages print to the terminal but never reach WhatsApp.

Steps:
  1. Go to console.twilio.com → sign up for a free account
  2. From the dashboard, copy your Account SID and Auth Token
  3. In the left menu: Messaging → Try it out → Send a WhatsApp message → follow the sandbox join instructions (send a WhatsApp to the sandbox number)
  4. The sandbox number is your TWILIO_WHATSAPP_FROM (format: whatsapp:+14155238886)
  5. Open tramed/.env and replace the four placeholder values:
TWILIO_ACCOUNT_SID=ACyour_actual_sid_here
TWILIO_AUTH_TOKEN=your_actual_token_here
TWILIO_WHATSAPP_FROM=whatsapp:+14155238886
PHARMACIST_WHATSAPP=whatsapp:+250788301960

⚠ The sandbox requires every recipient to first send the join message to Twilio. For a real deployment, upgrade to a paid Twilio WhatsApp sender.

! 2. Host the app on a server that runs 24/7

APScheduler lives inside the Flask process. If the laptop running the app is shut down or closed, the scheduler stops and the Monday 08:00 job never fires. The app needs to run on a machine that is always on.

Options (cheapest to most robust):
Option A — Railway (recommended for now)
Free tier available. Push your code to GitHub, connect Railway, it deploys automatically. Supports SQLite. Add your .env variables in Railway's environment settings.
railway.app → New Project → Deploy from GitHub
Option B — DigitalOcean Droplet ($6/month)
A small Ubuntu VPS. Run the Flask app as a systemd service so it restarts automatically on reboot. More control, slightly more setup.
Option C — Old laptop / Raspberry Pi (pharmacy premises)
Run the server on-site. Free but dependent on local power and internet. Good for a pilot before spending on cloud hosting.
3. Build: daily automated patient reminders

The message text already exists in retention.py (_reminder_message_text). What's missing is a scheduled job that sends it automatically.

# Add this job to app.py next to weekly_reorder_summary
@scheduler.task("cron", id="daily_reminders", hour=9, minute=0)
def daily_patient_reminders():
    with app.app_context():
        from retention import get_due_reminders
        from notifier import send_whatsapp
        due = get_due_reminders(days_ahead=0)
        for r in due:
            send_whatsapp(r["whatsapp_url"], r["message"])

⚠ Before enabling this, make sure every customer has opted in to receive WhatsApp messages — sending unsolicited messages can get your Twilio number flagged.

4. Build: weekly automated supplier reorders

Same pattern as the pharmacist summary but sends to each supplier. The message text and grouping logic already exists in get_supplier_reorder_messages().

@scheduler.task("cron", id="weekly_supplier_reorders", day_of_week="mon", hour=8, minute=30)
def weekly_supplier_reorders():
    with app.app_context():
        from retention import get_supplier_reorder_messages
        from notifier import send_whatsapp
        for sm in get_supplier_reorder_messages():
            to = "whatsapp:+" + sm["supplier"].phone
            send_whatsapp(to, sm["message"])

How to Test the Scheduler Right Now (Without Twilio)

You don't need to wait until Monday or have Twilio credentials to verify the job works. Temporarily change the cron schedule to fire every 2 minutes, restart the app, and watch the terminal.

# In app.py — change this temporarily:
@scheduler.task("cron", id="weekly_reorder_summary", minute="*/2")
# Restart the app and watch the terminal.
# You'll see the full WhatsApp message printed every 2 minutes.
# Change back to the real schedule when done:
@scheduler.task("cron", id="weekly_reorder_summary", day_of_week="mon", hour=8, minute=0)
